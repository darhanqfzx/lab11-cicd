# Ответы для устной защиты

1. CI — автоматические проверки изменений. Continuous delivery — подготовка артефакта к выпуску с ручным решением о развёртывании. Continuous deployment — автоматическое развёртывание. Здесь CI и публикация контейнера; deployment пока не настроен.
2. PR запускает lint, test и secrets-scan. Push в main или тега v* дополнительно запускает image после успешных проверок. У image условие github.event_name == 'push'.
3. Matrix запускает тесты отдельно на Python 3.11 и 3.12. Кэш pip сохраняет скачанные пакеты, установка всё равно выполняется.
4. contents: read даёт минимальные права чтения кода; только image нужны packages: write. GITHUB_TOKEN — временный токен workflow, предоставляемый GitHub.
5. Main получает main и sha-…; v1.0.0 получает 1.0.0 и sha-…. Для релиза выбираем 1.0.0; digest точнее фиксирует содержимое образа.
6. Trivy проверяет пакеты образа. Фактические CVE нужно показать из собственного лога. Обновляем пакеты; исключение — только с причиной, владельцем и датой пересмотра.
7. Ruleset требует успешных четырёх проверок и PR. Красный обязательный check блокирует merge. Сам workflow без ruleset слияние не запрещает.
8. Environment production позволяет требовать approval и выдавать секреты только после него. Rollback запускает старый опубликованный образ без новой сборки. Stretch в этом проекте пока не настроен.
